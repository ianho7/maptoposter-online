# 海岸线拓扑分类 V2 实施计划

## Implementation Status（2026-08-01）

核心实现与离线验证已完成，真实应用 PNG/SVG 接受面仍待验收：

- 生成器已升级为 `directed-coastline-v2`，缓存已升级为 `v12-coastline-topology-v2`。
- 固定 `6,000` 段预算和左右偏移采样已被分辨率感知简化、带来源切分及精确边邻接替代。
- 生产阈值最终采用：`0.25px` 初始容差、`0.5px` 最大容差、`10,000` 目标段数、`20,000` 硬上限。
- 完整里斯本输入：`21,521` 段简化为 `6,762` 段，容差 `8.333m`，生成 `4` 个可信海面；当前开发机离线总耗时约 `0.74s`。
- 里斯本外海点 `[-9.30, 38.62]` 为水，市中心 `[-9.14843, 38.72635]` 非水。
- 海岸线相关测试 `33 pass`，水体/绿地语义测试 `6 pass`，类型检查和生产构建通过。
- 尚未完成：重启真实开发服务后导出里斯本 PNG/SVG，以及纽约、海口、南京最终视觉回归。

## Objective

根治“高密度或局部异常海岸线导致整片海面消失”的问题，同时维持此前纽约案例建立的安全原则：不确定时不得覆盖陆地。

本次范围：

- 解决里斯本因 `21,521 > 6,000` 条线段而整批跳过的问题。
- 移除“左右偏移采样点”分类方式。
- 将全局失败改为按候选区域独立接受或拒绝。
- 保持现有 OSM / Overpass 数据源、Water GeoJSON 输出和 WASM 绘制接口不变。
- 不修改绿地、道路、POI 或 WASM 绘制逻辑。
- 提交约 0.8 MB、仅含必要海岸线的里斯本回归数据，不提交完整原始水体文件。

## Background and Context

项目目前通过 OSM `natural=coastline` 有向线补出可填色海面。此前纽约案例证明，不能用海报中心点区分海陆；当前实现因此改用“沿 OSM 海岸线方向前进时，右侧为水、左侧为陆”的方向证据，并在输入不确定时安全缺海。

该原则避免了陆地被海水覆盖，但里斯本暴露了两个新的系统性边界：固定线段预算会让高精度海岸线整批退出，任意局部采样歧义也会让整座城市的生成海面归零。需要在不放松陆地保护的前提下，把海陆判断从坐标偏移采样升级为拓扑邻接判断。

重要模块：

- `src/services/sea-polygons.ts`：海岸线裁切、围合、分类和海面合并。
- `src/data-worker.ts`：调用海面生成器并输出诊断汇总。
- `src/lib/poster-viewport.ts`：统一查询范围与地图数据缓存版本。
- `src/services/sea-polygons.test.ts`：方向、多陆地、预算和海口回归测试。

约束：

- 不更换 OSM / Overpass 数据源。
- 不引入全球海陆边界数据。
- 不依赖浏览器自动化完成核心回归。
- 不提交用户导出的完整 10 MB 里斯本原始水体文件。

## Current State Analysis

当前 `sea-polygons.ts` 的处理方式是：

1. 裁切海岸线。
2. 超过 `6,000` 条线段便返回空结果。
3. 使用 JSTS 切分并围合候选区域。
4. 在每条有向海岸线左右生成偏移采样点。
5. 任意采样失败便返回空结果。
6. 仅生成有水侧证据、无陆侧证据并触及查询边界的区域。

里斯本离线证据：

```text
输入海岸线要素：549
原始线段：28,482
裁切后线段：21,521
退出原因：processing-budget
生成海面：0
```

轻度简化后还能复现第二层问题：约 61 条局部线段无法通过偏移采样定位候选区域。简单提高预算或跳过第一条歧义线都不足以恢复西南外海。

项目已有 `jsts@2.12.1`，其中包含本方案需要的 `TopologyPreservingSimplifier`、`NodedSegmentString`、`MCIndexSnapRounder` 和 `Polygonizer`，无需增加依赖。

## Proposed Solution

### 1. 分辨率感知的拓扑保形预处理

在本地米制坐标中处理海岸线：

- 使用以查询中心为原点的局部等距近似投影：
  - `x = Δlon × cos(centerLat) × 111320`
  - `y = Δlat × 111320`
  - 输出前进行逆变换。
- 删除连续重复点、零长度线段和完全重复的同向/反向线段。
- 将全部裁切海岸线组成 `MultiLineString`，使用现有 JSTS `TopologyPreservingSimplifier` 整体简化，保持端点、线间拓扑和原始方向。
- 简化容差按最大支持分辨率计算：
  - 初始容差：查询范围最大边对应 `0.25` 个像素；
  - 若线段仍超过目标值，将容差提升到 `0.5` 个像素；
  - 不允许超过 `0.5` 像素，防止肉眼可见的岸线漂移。
- 目标线段数为 `10,000`，允许继续处理的硬上限为 `20,000`。
- 达到最大容差后仍超过硬上限才安全降级，并记录 `processing-budget-after-simplification`。

简化前后的线条数量、容差和耗时必须进入诊断数据。

### 2. 保留来源和方向的线段切分

用 JSTS 的底层切分接口替换当前丢失来源信息的 `GeometryNoder` 包装：

- 为每条海岸线创建 `NodedSegmentString`，附带：
  - `kind: "coastline"`
  - 原始要素编号
  - 原始方向
- 查询范围四条边同样进入切分，但标记为 `kind: "viewport-boundary"`。
- 使用 `MCIndexSnapRounder` 和米制 `PrecisionModel(1000)`，以毫米级精度统一交点。
- 切分产生的新线段继承原始海岸线方向和来源。
- 将切分后的全部线段交给现有 `Polygonizer` 生成互不重叠的候选区域。

`buildSeaPolygonsWithDiagnostics()` 的现有调用签名保持不变。

### 3. 用区域边界拓扑取代左右采样

新增内部模块 `src/services/coastline-topology.ts`，负责建立“有向海岸线边—候选区域”映射：

1. 遍历每个候选区域的外环和内洞。
2. 按米制精度生成无方向的线段键。
3. 根据环方向和外环/内洞身份，判断该区域位于线段的左侧还是右侧。
4. 将切分后的有向海岸线与同键区域边匹配。
5. 沿原始方向累计：
   - 右侧区域的水侧证据长度；
   - 左侧区域的陆侧证据长度。
6. 无法匹配的局部边只计入诊断，不再导致整批退出。

候选区域仅在同时满足以下条件时生成海面：

- 触及统一查询范围边界；
- 水侧证据不少于 `max(25 米, 4 × 简化容差)`；
- 陆侧证据为零；
- 面积大于现有最小面积限制；
- 输出多边形有效且不存在自相交。

如果一个区域证据冲突，只拒绝该区域；其他可信区域继续生成。现有显式湖泊、河面和水库多边形始终保留。

### 4. 版本、缓存与诊断

- 生成器版本升级为 `directed-coastline-v2`。
- 地图数据缓存版本升级为 `v12-coastline-topology-v2`，确保旧缺海结果不再命中。
- 扩展 `SeaPolygonDiagnostics`：
  - `input_segments`
  - `deduplicated_segments`
  - `simplified_segments`
  - `simplification_tolerance_m`
  - `noded_segments`
  - `matched_coastline_segments`
  - `unmatched_coastline_segments`
  - `candidate_faces`
  - `accepted_faces`
  - `rejected_conflict_faces`
  - `rejected_insufficient_support_faces`
  - 各阶段耗时和最终降级原因
- 后台线程仍只输出一次汇总日志，不增加逐线段日志。
- 更新 `FILETREE.md` 和现有海岸线方案/checklist，记录 V2 决策与诊断字段。

## Alternatives Considered

| 方案 | 结论 |
|---|---|
| 将 `6,000` 直接改为 `30,000` | 不采用；围合成本明显增加，左右采样歧义仍存在。 |
| 简化后继续使用偏移采样 | 不采用；里斯本实验仍出现局部歧义，无法稳定恢复西南外海。 |
| 遇到歧义直接 `continue` | 不采用；实验生成的区域仍不包含目标外海，也会降低陆地保护能力。 |
| 栅格洪水填充后转多边形 | 不采用；实现较简单，但边缘精度受分辨率影响，PNG/SVG 几何可能不一致。 |
| 自研完整半边图/DCEL | 暂不采用；现有 Polygonizer 能生成区域，只需建立精确的区域边界邻接关系。 |
| 全球海陆面数据源 | 不在范围内；准确度上限更高，但违反本次不更换数据源的约束。 |

## Implementation Plan

### Phase 1：建立红色回归基线

- Goal：让测试精确捕获里斯本西南外海缺失，并形成可离线执行的反馈环。
- Files：`src/services/sea-polygons.test.ts`、`src/services/fixtures/lisbon-coastline.geo.json`。
- Tasks：
  - 从里斯本原始文件中提取 549 个线状海岸线要素。
  - 删除其他水体、道路、绿地和无关属性，保存约 0.8 MB 的测试数据。
  - 增加失败测试：当前 V1 返回 `processing-budget`；`[-9.30, 38.62]` 必须位于生成海面；里斯本市区陆地点不得位于生成海面。
  - 增加合成性质测试：海岸线增加大量中间点后结果不变；加入无法匹配的局部线段不删除已有可信海面；输入顺序打乱不改变结果。
- Expected Result：当前代码稳定失败，测试精确捕获用户看到的问题。

### Phase 2：实现米制预处理和自适应简化

- Goal：在不产生可见岸线误差的前提下，把真实高密度输入降到可处理规模。
- Files：`src/services/sea-polygons.ts`、`src/services/coastline-topology.ts`。
- Tasks：
  - 增加局部投影、逆投影、清理和去重。
  - 接入 JSTS 拓扑保形简化。
  - 实现 `0.25px → 0.5px` 两级容差及 `10k/20k` 预算。
  - 验证简化保持每条线方向、开放线端点、闭合线闭合性及 MultiLineString 组件顺序和数量。
- Expected Result：里斯本进入切分阶段，简化误差不超过半个输出像素。

### Phase 3：实现带来源的切分和拓扑邻接分类

- Goal：彻底移除偏移采样和全局歧义退出。
- Files：`src/services/coastline-topology.ts`、`src/services/sea-polygons.ts`、`src/services/sea-polygons.test.ts`。
- Tasks：
  - 用 `NodedSegmentString` 与 `MCIndexSnapRounder` 保留来源和方向。
  - 复用 Polygonizer 生成候选区域。
  - 构建候选区域环线段索引。
  - 通过精确边匹配确定每个区域位于海岸线左侧还是右侧。
  - 删除偏移采样、空间网格点查询及 `ambiguous-segment` 全局返回路径。
  - 按候选区域独立接受或拒绝。
- Expected Result：里斯本西南外海生成；局部异常不影响其他区域；纽约陆地保护仍成立。

### Phase 4：缓存、日志和兼容处理

- Goal：确保 V2 真正在运行时生效，并让安全降级可定位。
- Files：`src/lib/poster-viewport.ts`、`src/data-worker.ts`、相关文档。
- Tasks：
  - 升级生成器及地图缓存版本。
  - 更新后台线程诊断日志字段。
  - 旧 `directed-coastline-v1` 生成面按现有旧版本逻辑移除并重新计算。
  - JSTS 切分或围合抛错时保留原始显式水体，记录 `topology-error`，不得输出部分未知状态的面。
- Expected Result：开发环境和用户缓存不会继续使用 V1 结果，失败仍为安全缺海。

### Phase 5：完整回归和性能验收

## Validation Strategy

### 自动测试

- 方向反转后左右水陆交换。
- 多块陆地不会因为不包含中心点而变成海。
- 岛屿闭环形成水面内洞，岛屿区域不被填水。
- 海岸线加密、简化和输入重排不改变关键采样点结果。
- 一个无效碎片不会删除其他有效海面。
- 冲突区域被拒绝，其他区域继续生成。
- 超过最大简化容差和硬上限时安全返回原始水体。
- 旧生成器版本不与 V2 结果共存。
- 里斯本回归点 `[-9.30, 38.62]` 位于海面。
- 纽约已知陆地点不位于生成海面。

### 性能验收

不在 CI 中设置脆弱的绝对时间断言，但记录阶段耗时。以当前开发机为验收环境：

- 分类阶段应明显低于切分和围合阶段。

## Risks and Mitigations

| 风险 | 影响 | 缓解与回退 |
|---|---|---|
| 简化造成岸线漂移或断口 | 海陆边界错位 | 全局拓扑保形简化、端点测试、最大 `0.5px` 容差；失败则使用未简化数据或安全缺海。 |
| 外环/内洞方向映射错误 | 岛屿或陆地被填水 | 针对顺逆时针外环、内洞和方向反转建立独立单元测试。 |
| 切分后边键因精度不一致无法匹配 | 海面缺失 | 所有几何统一使用米制 `PrecisionModel(1000)`，边键使用同一精度模型输出。 |
| 局部错误证据导致陆地覆盖 | 严重视觉回归 | 陆侧证据必须为零；冲突只拒绝区域，不能通过多数票覆盖陆地。 |
| 真实数据仍超过预算 | 局部缺海 | 自适应简化至 `0.5px`；仍超过 `20,000` 才保守降级，并明确记录原因。 |
| 缓存继续返回旧结果 | 修复看似无效 | 同时升级生成器版本和地图缓存版本；开发复测完整重启服务和页面。 |
| 测试依赖本地下载目录 | CI 无法复现 | 提交去属性、仅含海岸线的里斯本精简回归数据。 |

## Open Questions

无阻塞问题。以下决策已经确认：

- 采用拓扑分类 V2，不做分阶段采样修补。
- 允许提交约 0.8 MB 的里斯本精简海岸线回归数据。
- 不增加 npm 依赖，复用项目已有 `jsts`。
- 不变更 Overpass 查询、Worker 消息协议和 WASM 接口。
- 不承诺修复 OSM 本身缺失、严重断裂或方向错误的数据；这些情况继续安全缺海并输出诊断。
